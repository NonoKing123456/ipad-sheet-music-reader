# iPad Sheet Music Reader

Source-only iPad build repository for version **0.6.0+10**. No scores, user state, credentials, or local build outputs are included.

On Windows, select the score folder and press **连接我的 iPad** to display a large QR code. On iPad, press **扫描电脑二维码** once; the app remembers the authenticated connection and immediately downloads the library. Later use **立即同步** with the computer reader open on the same Wi-Fi. Rescan after the computer changes networks. Addresses, ports and pairing codes are inside optional advanced diagnostics. Pairing codes remain single-use and expire in two minutes; no network-wide discovery is used.

The workflow builds a native iPad/iPhone device application with Flutter **3.47.8** (revision `737ba8f885dc774b53b442759999a312c9461e4e`), standard **macos-26 arm64**, and **Xcode 26.6**. It creates an **unsigned** `Payload/Runner.app` IPA container, SHA-256 checksum, and build information. Every nested Mach-O must report **IOS / arm64** before packaging.

## Build and download

1. This repository contains only the reviewed application source, which the owner has authorized for public release. Never add scores, user state, credentials, or unreviewed working files.
2. Only this public repository, its owner, and the standard runner are allowed. GitHub provides standard hosted runners free for public repositories; private and larger runners are excluded. No Actions artifact storage is used. Outputs are published as public prerelease assets, each strictly smaller than 2 GiB. See [Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions), [standard runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners), and [release limits](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases).
3. The initial `main` push containing `.github/workflows/ios-unsigned.yml` triggers the build. Later pushes trigger it only when that workflow path changes. For a manual run, as the owner open **Actions → iOS unsigned device build → Run workflow**, and enable `public_source_confirmed` (default false). Pull requests do not trigger it. Do not switch to a private repository or paid runner to resolve a failure.
4. Download the three assets from prerelease `unsigned-ipad-<run number>-<attempt>`, inspect build information, and verify the IPA checksum. The job has a 25-minute limit; a failure produces no successful delivery claim. Prereleases are not marked latest. The job has repository contents write permission solely to publish these assets; `GH_TOKEN` is passed only to the final publishing step, and checkout credentials are not persisted.

Mobile startup opens the searchable synced folder library directly. Reading fits the whole page to the actual screen, with floating tools toggled by a central tap. The central tap directly reveals compact annotation tools. System stylus events write or locally erase; touch gestures never draw ink. Two fingers pan/zoom in every tool state. Edge taps, swipes and PageUp/PageDown turn pages with a directional slide once the next paper and its matching annotations are ready; the old surface and bookmark remain until presentation succeeds. Device simulation is available only as an explicitly named Windows development preview. Offline presentation uses cached metadata; link and content validation remain at actual read/write boundaries.

**Status:** Version 0.6.0+10 passed focused Windows-hosted readiness, animation, stylus/touch, local eraser, persistence/merge, focus and mobile geometry checks. These deterministic synthetic checks are not iPad frame-rate or third-party pen measurements. The new native iPad build and real-device behavior still need verification. The existing macOS system-alias smoke remains mandatory before the cloud build. Keep the same bundle ID and local signing identity when updating; do not uninstall or clear existing data. The unsigned IPA requires local signing before installation. No Apple credentials or personal scores are uploaded.
